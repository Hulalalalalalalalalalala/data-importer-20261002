# Data Importer

Normalize a CSV file or JSONL file to JSONL using a small explicit schema. Requires Python 3.10+; no installation dependencies.

`python3 data_importer.py samples/customers.csv --schema samples/schema.json --output customers.jsonl --errors errors.jsonl` converts the two valid sample rows. `samples/mixed.csv` contains one accepted row and two rejected rows. Each rejected row is written separately with its logical CSV record number (header is 1) and field errors; accepted rows remain available.

JSONL input is selected with `--format jsonl` (`--format csv` is the default; the format is never inferred from the file extension). `python3 data_importer.py samples/customers.jsonl --schema samples/schema.json --format jsonl --output customers.jsonl --errors errors.jsonl` normalizes the JSONL sample, and `samples/mixed.jsonl` mirrors the mixed CSV sample. JSONL is read as UTF-8 with an optional leading BOM. Each non-empty physical line must contain exactly one JSON object; blank and whitespace-only lines are skipped while keeping the physical, 1-based line number, and empty or blank-only files produce zero counts. Accepted records keep input order.

For JSONL the set of source keys must match the schema's effective sources exactly (literal names, any order; no missing or extra keys), and top-level duplicate keys reject the line. Values reuse the same semantics as CSV: strings are trimmed, with empty strings and `null` becoming JSON null for optional columns or rejecting a required column. `string` accepts only JSON strings; `integer` accepts JSON integers (but not booleans) or strings convertible under the existing CSV rules, rejecting JSON decimals and exponents; `boolean` accepts JSON booleans or case-insensitive `true`/`false` strings. Arrays, objects and other types are never implicitly converted. Invalid JSON, non-object top-level values, key-set violations and the `NaN`, `Infinity` and `-Infinity` constants reject their line only; later lines are still processed. Parse errors, structure errors and field errors are reported separately, with field errors keyed by output field name and collected in schema order.

Schema columns specify name, type (`string`, `integer`, `boolean`) and optional `required`. A column may also declare an optional `source`: the CSV column or JSONL source key it reads from, while `name` remains the output field name; omitting `source` reads the column named by `name`. An explicit `source` must be a non-empty, non-blank string, and the effective source names must be unique across columns (a source may coincide with another field's `name`, and two fields may swap sources). For CSV the header must match the effective source names and their order exactly, compared literally without trimming or case folding. Text is trimmed, absent optional values become JSON null, and booleans accept true/false without case sensitivity. Output objects use sorted keys. The input is processed in memory. Outputs replace existing files but cannot alias either input or each other; parent output directories must already exist. CLI exit codes are 0 for no rejected rows, 1 for row errors and 2 for invalid configuration (including an unknown `--format`, mapping or header mismatches), unreadable input, or other I/O errors; in those cases a JSON object with an `error` key is printed to standard output and existing output files are left untouched.

The public API is `normalize_csv(source, schema)` and `normalize_jsonl(source, schema)`, each returning records, errors and counts. JSONL file-open failures raise `OSError` and decoding failures raise `UnicodeDecodeError`. `write_jsonl(path, records)` persists either sequence deterministically. Repeated processing of the same offline input yields identical records, error ordering and counts. Run `python3 -B -m unittest -v` for API conversion and CLI checks.
