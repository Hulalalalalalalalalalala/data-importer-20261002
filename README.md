# Data Importer

Normalize a CSV file to JSONL using a small explicit schema. Requires Python 3.10+; no installation dependencies.

`python3 data_importer.py samples/customers.csv --schema samples/schema.json --output customers.jsonl --errors errors.jsonl` converts the two valid sample rows. `samples/mixed.csv` contains one accepted row and two rejected rows. Each rejected row is written separately with its logical CSV record number (header is 1) and field errors; accepted rows remain available.

Schema columns specify name, type (`string`, `integer`, `boolean`) and optional `required`. An optional `source` names the CSV column that feeds a field; `name` stays the output field name and is used when `source` is omitted. Sources are matched literally (no trimming or case folding) and must be unique once defaults are applied — explicit sources may swap columns or coincide with other target names as long as no effective source repeats. The header must match the effective sources and their order exactly: missing, extra, duplicate or reordered columns raise `ValueError`. A non-string or blank `source` also raises `ValueError`; configuration errors identify the affected target field (and the conflicting source). Text is trimmed, absent optional values become JSON null, and booleans accept true/false without case sensitivity. Output objects use sorted keys. The input is processed in memory. Outputs replace existing files but cannot alias either input or each other; parent output directories must already exist. CLI exit codes are 0 for no rejected rows, 1 for row errors and 2 for invalid configuration or I/O errors (configuration and header errors leave any existing output files untouched).

The public API is `normalize_csv(source, schema)`, returning records, errors and counts. `write_jsonl(path, records)` persists either sequence. Run `python3 -B -m unittest -v` for API conversion and CLI checks.
