# Data Importer

Normalize a CSV file or JSONL stream to JSONL using a small explicit schema. Requires Python 3.10+; no installation dependencies.

`python3 data_importer.py samples/customers.csv --schema samples/schema.json --output customers.jsonl --errors errors.jsonl` converts the two valid CSV rows. The input format is chosen explicitly with `--format csv` (default) or `--format jsonl`; it is never inferred from the file extension. For JSONL, use `python3 data_importer.py samples/customers.jsonl --schema samples/schema.json --output customers.jsonl --errors errors.jsonl --format jsonl`. `samples/mixed.csv` and `samples/mixed.jsonl` each contain one accepted row and two rejected rows. Each rejected row is written separately with its physical line number (for CSV the header is line 1) and its errors; accepted rows remain available in input order.

Schema columns specify name, type (`string`, `integer`, `boolean`) and optional `required`. A column may also declare an optional `source`: the CSV column, or JSONL object key, it reads from, while `name` remains the output field name; omitting `source` reads the field named by `name`. An explicit `source` must be a non-empty, non-blank string, and the effective source names must be unique across columns (a source may coincide with another field's `name`, and two fields may swap sources). For CSV the header must match the effective source names and their order exactly, compared literally without trimming or case folding. For JSONL each non-empty line must hold exactly one JSON object whose key set equals the effective source set exactly (order is free, keys match literally); missing or extra keys reject the line.

CSV text is trimmed, absent optional values become JSON null, and booleans accept true/false without case sensitivity. JSONL is read as UTF-8, allowing a leading byte-order mark; blank lines are skipped while still consuming a physical line number, and an empty or all-blank file reports zero counts. Each line is parsed independently: invalid JSON, a non-object top-level value, duplicate top-level keys, and the `NaN`, `Infinity` and `-Infinity` constants reject that line and later lines are still processed. String values are trimmed; trimmed-to-empty strings and JSON null follow the same required/null rule as CSV. The `string` type accepts JSON strings only; `integer` accepts non-boolean JSON integers or strings convertible under the CSV rule (fractional and exponential JSON numbers are rejected); `boolean` accepts JSON booleans or case-insensitive `true`/`false` strings. Arrays, objects and any other value never convert implicitly and are reported as field errors. Error messages distinguish parse, structure and field errors; field errors use the output field name and are collected in schema order. Output objects use sorted keys. The input is processed in memory. Outputs replace existing files but cannot alias either input or each other; parent output directories must already exist. CLI exit codes are 0 for no rejected rows, 1 for row errors and 2 for an invalid format or configuration (including mapping, header or key-set mismatches, or an invalid `--duplicate-by` field), unreadable input, or other I/O errors; in that case standard output carries a JSON object with an `error` key and existing output files are left untouched.

Both functions accept an optional `duplicate_by` keyword argument: a non-empty list of output field names, matched literally against schema `name` values (source names are not accepted), without repeats. When given, the result gains a `duplicates` array computed only over records that passed validation. Records are compared on their mapped, trimmed and type-converted values, so on an integer column the JSON integer `3` equals the convertible string `"3"`; string comparison stays case-sensitive and null compares equal to null. Each group appears as `{"key": {field: converted_value, ...}, "record_numbers": [...]}`; the key lists the specified fields in the given order, and `record_numbers` are one-based positions in `records` (rejected rows and blank JSONL lines do not occupy a position), never physical line numbers. Keys seen only once are omitted, groups are ordered by the first member's position, and the numbers within a group are ascending. With no duplicates the array is empty; duplicates are never counted as rejections, never removed, and do not change the records or errors files. An omitted option or `None` leaves the result unchanged. On the CLI, pass the repeatable `--duplicate-by FIELD` once per field in the desired order; when used, the printed summary also carries `duplicates`. An invalid configuration (not a list, empty, a blank or non-string entry, a repeated entry, or an unknown field) raises `ValueError`, naming the offending entry, before the input file is opened; on the CLI this exits 2 with an `error` object and neither output file is created or replaced.

The public API is `normalize_csv(source, schema, duplicate_by=None)` and `normalize_jsonl(source, schema, duplicate_by=None)`, each returning records, errors, counts, and, optionally, duplicates. JSONL file-open failures raise `OSError` and undecodable bytes raise `UnicodeDecodeError`. `write_jsonl(path, records)` persists either sequence with deterministic serialization. Run `python3 -B -m unittest -v` for API conversion and CLI checks.
